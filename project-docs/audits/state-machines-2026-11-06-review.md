# Review of the state machine audit, 2026-11-06

Independent review of `state-machines-2026-11-06.md` and its repro suite. I read the app code myself, reran the audit's suite once, and wrote a second suite that drives the UI's own entry points. No app code was changed and nothing was fixed.

**Summary: 10 claims. 1 CONFIRMED, 8 CONFIRMED-MINOR, 0 NOT A BUG, 1 UNVERIFIED. False-positive rate 0 of 9 decided claims. The audit overstated reach on 5 claims (S2, S3, S4, S5, S10) and the ranking changes (S8 moves to second). Of the 9 product calls I agree with 7, CALL-5 is not an issue and CALL-8 is a bigger risk than "product call" suggests.**

## Missed by the audit (within its scope)

- **S1 also reaches pills through the nudge.** After a westward move, `nextUnclaimedOccurrence` returns today's slot for a pill already logged today, so a Pro scheduler pass nudges about a logged pill (my daily test). Home's daily rule is not affected.
- **S8's harmful direction.** Lengthening the wait sends the "wait is over" ping early (code reasoning on the same path the audit test proves).

I found no other serious state bugs in the audited machines.

## Method changes that would have prevented the errors

1. **List a scheduler's real triggers before writing the route.** S2's "open or log" and "every scheduler pass" came from not separating cold launch from resume (`SimpleGLPApp.swift:182-201`), and from not seeing that logging the overdue dose claims it.
2. **Apply defaults and tiers when sizing impact.** Proactive Alerts is opt-in and off by default, so S2 to S5 reach a slice of Pro. The wait ping is free, so S8 reaches more users than the ranking gave it.
3. **Drive the entry point the UI uses.** The audit proved S3 through the Siri path and S7 with a seeded request. The conclusions held, but the Home route has its own timing (Undo before the health task finishes leaves the nudge alone). A test should call what the button calls.
4. **Follow each effect through every guard to what the user sees.** S9's "slot reads unclaimed" and S1's "until the next dose is logged" describe stored state, not the screen. `ScheduleEngine.swift:189` hides S9 on Home, and S1 ends when the next slot passes.
5. **Cite the promise nearest the action.** S7 has a direct promise in its own sheet (`LogEarlierSheet.swift:100-101`). S10 cited a widget comment for a Home claim.
6. **Use the existing seams before calling a claim "Code path".** S9 needed only `captureShot` and the delete sequence, not a copy of the sheet. Leave claims that really can't be proven out of the ranked table, as S10 should have been.
